# V0.3.2 — BRAIN Evidence Reliability

本版继续使用一个 Research Agent，不新增 Agent 角色。主要修复单日 PnL 证据的日期完整性，以及部分 IS 时段无法满足三个完整自然年门槛的问题。

## 已复现及修复

旧版原有 96 项测试通过；新增回归在旧版失败：`2020-01-02:1.0` 到 `2023-09-29:7.0` 在没有交易日历时仍返回 6.0 的差分。现在无日历调用被拒绝。即使显式提供只有这两个日期的稀疏日历，也不能把多年跨度认证为一个常规日频观测。

新流程先核实服务器精确 IS 边界，再核实 PnL 数据语义及交易日历。只接受已声明的交易会话收盘累计现金 PnL、区间内无重置且固定本金的协议。不推测单期/累计值，不通过数值曲线的形状“识别”重置，也不把 bookSize 存在当作其始终恒定的证明。审核人须依据当前账户的字段说明、真实响应和独立对照确认这些语义。实际平台若采用不同协议，本适配器保持缺证据，须另行实现并验证适配器。

**真实账户 PnL 语义尚未核实。** 本次环境没有 BRAIN 凭据，不能把脚本化响应或公开网页替代当前账户验收。契约默认关闭，软件修复完成不等于真实接入通过。

## 两个不同的契约

`[brain.discovery_evidence]` 沿用 v0.3.1，核实服务器 `is` 区域内精确 `YYYY-MM-DD` 起止日期及包含端点语义。没有可靠边界，不请求混合样本的年度/PnL 序列。

`[brain.pnl_evidence]` 新增以下字段，默认均未核实：

| 字段 | 审核依据 |
|---|---|
| `reviewed`, `review_note` | 当前账户中累计/现金单位、无重置、固定本金与收盘日期语义的核实记录 |
| `value_semantics` | 仅支持 `cumulative_cash_pnl_constant_capital_session_close`；其他值拒绝 |
| `capital_path` | 服务器详情中正有限固定本金的字段路径数组；无默认猜测路径 |
| `calendar_reviewed`, `calendar_review_note` | 负责人核实交易日历完整性，确认未列日期确为休市 |
| `calendar_id`, `calendar_source`, `calendar_region` | 日历身份、来源和与 scope 一致的区域 |
| `calendar_start`, `calendar_end` | 日历声明的完整覆盖区间，须覆盖整个待验证 IS |
| `calendar_file`, `calendar_sha256` | 本机 CSV 路径及审核后的字节哈希；相对路径从配置项目根解析 |

日历 CSV 只有 `date` 列，日期严格有序、无重复；每一行是一场应有交易会话。未列日期的“休市”语义由审核人确认，不由星期规则猜测。本版不附假冒真实市场的日历，也不自动拉取未经授权的数据。

```text
date
YYYY-MM-DD
YYYY-MM-DD
```

文件限制 5 MB、30000 场会话。日频协议还保守拒绝相邻会话自然日间隔超过 14 日的情况，防止明显稀疏的日历将多年跨度标为一天；这是本软件的支持边界，不是交易所或 BRAIN 的官方规则。长停市、跨市场或周末记账序列需要专门核实适配，不能绕过缺口检查。哈希、reviewed 标记及来源说明均可被文件系统持有者伪造，因此仍只是防误操作机制。

配置中故意不提供“可直接改成 true”的真实字段名样例。测试里的 `is.bookSize` 等只是合成 fixture。若真实接口存在周末零值、分段累计重置或动态本金，不能照搬该 fixture 契约。

## 缺口如何处理

- 先限制在精确 IS 内，再检查记录日期和有限数值；不保存 OS 数值到研究记忆。
- 只有排序后相邻两条记录同时是日历中相邻会话时，才计算一个日收益差分；两个端点都必须在 IS 内。
- 跨过应有会话的差分不保存聚合 PnL 值，记录 `gap_intervals` 的起止与缺失会话数。缺失边界日期记录在 `missing_dates`；非会话记录单列。不会补零、插值、连桥或重新切窗避开缺口。
- 合法的周末/经审核休市间隔可以跨越；缺失一个应有交易日会阻止完整性状态。
- `daily_evidence` 保存协议、日历和契约指纹、会话日期、观测覆盖及异常；`daily_returns` 是以经核实的固定本金归一的现金 PnL 差分，不能直接宣称已扣除所有现实成本。
- 评价器重新检查预期键集、完整覆盖、隔离边界、数值一致性和本金归一关系；修改 `status=complete` 不能弥补缺观测。旧版只有 IS 边界来源的 PnL 不自动成为可靠日频证据。
- 多样性筛选仍用相同双端点键对齐，且不混用不同日历或语义契约。缺证据公式可保留研究队列，不能进入提交评审池。

前瞻 BRAIN 更新也采用冻结的同一语义契约、日历核验和完整会话检查。存在缺口时不追加伪单日收益；旧追踪记录没有冻结契约时，不隐式赋予可靠性。负责人导入的外部 CSV 仍是单独来源的每观测收益，不自动获得日频年化资格。

## 固定非重叠稳定性窗口

V0.3.1 的门槛需要三个完整自然年，因而 `2020-07-01..2023-06-30` 即使有约三年历史，也最多提供 2021、2022 两个整年统计。本版不再把这个年度计数作为稳定性门槛，年度接口不可用也不直接导致稳定性缺失。

新版固定策略在 `config/evaluation.toml`：

```toml
version = "research-v2-fixed-session-windows"
stability_window_sessions = 126
min_stability_windows = 4
stability_annualization = 252
min_positive_window_fraction = 0.67
min_window_sharpe = -0.25
```

窗口从 IS 首个会话开始：每 126 个相邻会话收益构成一窗；相邻窗口可共享用于累计差分的边界锚点，但不共享任何一个收益观测。至少 4 个完整窗口，即至少 504 个日收益观测。所有应有会话必须完整，任何缺口都会使稳定性证据不完整；报告仍显示固定块的覆盖率，不能跳过坏块只留下好块。

未满 126 个观测的尾部通过 `trailing_observations` 明确报告，不算完整窗口，也不通过移动锚点把它凑进一个更有利的窗口。全 IS 的交易日完整性检查仍包括尾部。这意味着窗口评分不声称覆盖每一个尾部收益，须结合全 IS 的平台指标判断。

固定本金归一收益按样本标准差计算窗口 Sharpe；零方差/溢出不返回无限好指标，而是缺证据。正窗口比例及最差窗口分数用于固定门槛。输出为 `positive_window_fraction`、`worst_window_sharpe` 和 `stability.windows`。Pareto 排序也改用最差窗口；不再把窗口指标伪装为 `worst_year_sharpe`。这些是本地研究诊断，不是 BRAIN 报告的 Sharpe/Fitness。

**这是一次明确的研究政策变更。** 504 日观测要求与三个完整自然年的规则不同，不能宣称两者强度相同或直接比较新旧通过率。上述参数是示例研究规则，不是官方提交要求。必须在新研究前冻结，Agent 无修改权限，也不得为某个候选临时换窗长、起点或最少窗口数。历史不足仍进入缺证据队列，不自动缩短窗口放行。使用同一新策略重新开展两实验臂，才可比较效率。

## 单 Alpha 的真实验收步骤

当前环境无账户凭据，以下命令未在真实账户执行。账户身份验证、字段权限、实际配额和提交资格以服务端为准；不会绕过验证码或登录。

```bash
python -m alpharesearch doctor
python -m alpharesearch probe-api --output state/catalog-probe.json
python -m alpharesearch probe-api --one-simulation --expression "rank(close)" --output state/smoke-001.json
```

需要恢复轮询时只执行 `resume-probe state/smoke-001.json`，不重新创建模拟。`rank(close)` 仅测试协议，不以获得合格 Alpha 为验收标准。之后依据实际响应核实并填写两个契约及完整交易日历，再对同一 Alpha 执行：

```bash
python -m alpharesearch probe-evidence state/smoke-001.json --output state/evidence-001.json
```

身份认证仍可能 POST 登录，证据读取只 GET；没有模拟/提交 POST。对账包含账户与 API 地址、精确 Alpha ID、公式、设置、Sharpe/Fitness/Turnover、与旧指标的变化、IS 边界、PnL 契约、日历覆盖及来源指纹。响应形状写入脱敏追踪文件，不公开保存真实账户 fixture。私有验收结果权限为 0600，不能将其上传到公开下载页。

原始指标变化会如实保留，不因与旧记录不同而悄悄覆盖；公式/设置/ID 对不上则拒绝生成通过记录。`real_account_acceptance_completed` 只有在本次账户 HTTP 观测、来源对账及完整日频证据同时通过时才可能为 true；脚本化传输不计作真实通过。它不代表金融有效性、固定评价全通过或平台愿意接收提交。本地 JSON 标记及哈希均不是平台签名/授权凭证。

## 兼容性及本次范围

源码和研究政策变化后不直接恢复旧 run。旧年度字段的外部报告消费者须迁移到新的窗口字段；旧 SQLite 事实不重写。需要新研究或只读重新收集来源与日频证据，不能把旧缓存改个版本号就放行。

v0.3.1 的共享留出登记与固定 `local-daily-final-v1` 权限身份继续沿用；本补丁不重置已揭示区间。旧最终报告仍可读取；源码变化后的旧冻结计划不能继续重新评价，已使用数据不能因升级再次成为留出。

未完成：当前账户的真实 API/语义/日历验收、真实 LLM 与固定规则同预算实验、真实市场有效性、300 资产限制扩展及 BRAIN 组合设置等价。真实批量研究、自动提交继续关闭。合成 Demo 的零候选或高 Sharpe 均不能证明发现能力。
