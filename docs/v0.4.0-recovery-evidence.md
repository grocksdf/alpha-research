# v0.4.0：恢复、证据与定向实验

基于 `grocksdf/alpha-research` 的 `1eba5d8`，不增加 Agent。
本次实现软件并完成离线回归。没有 BRAIN 凭据、四个已有 Alpha 的 ID/响应或独立市场面板，未登录、未创建真实模拟、未提交。

## 1. 失效 Location 和不确定创建

```bash
python -m alpharesearch resume-probe state/smoke-001.json
```

依次使用已绑定 Alpha ID、原 Simulation Location、当前账户 Alpha 列表与详情 GET。
Location 过期、404 或返回失败不等于 Alpha 不存在；`dispatching/uncertain` 且无 Location 也可恢复。
自动认领要求账户/API 一致、详情 REGULAR 类型、公式 AST、关键设置与发送记录相符，
并有带时区且不早于发送时间的 `dateCreated`。不猜测时钟偏差。
账户列表必须完整分页且恰好一个匹配；零/多匹配、未知 schema、分页重复/不完整/总数变动均停止。

默认上限 1000 个 Alpha、每页 100。超过上限不依赖局部唯一性认领。
负责人确认精确 ID 后可运行：

```bash
python -m alpharesearch resume-probe state/smoke-001.json --alpha-id EXACT_EXISTING_ID
```

显式 ID 仍须出现在当前账户列表且详情一致，不再要求全局公式唯一性。
若 ID 位于扫描上限之后，调整固定 GET 扫描预算再只读重试。
这是操作恢复，不是服务端幂等键，也不能证明某对象一定由某个 POST 创建。

所有恢复路径不调用 Simulation POST；未知创建仍占预算，不重新放入 queued。
同研究范围仍有未知创建时，事务阻止其他新建任务 POST。
接收 Alpha ID 后先持久化绑定再读指标，读指标失败不丢失 ID。

### 研究任务与旧版本任务

```bash
python -m alpharesearch resume RUN_ID
python -m alpharesearch recover-trial RUN_ID TRIAL_ID
python -m alpharesearch recover-trial RUN_ID TRIAL_ID --alpha-id EXACT_EXISTING_ID
```

`resume` 默认只读恢复已经发送的任务，不运行 queued，不增加扰动。
继续新研究须显式使用 `--continue-research`，并保持账户、真实研究开关和预算有效。

旧版 run 因源码快照不同不能普通 resume 新研究；`recover-trial` 可跨版本只读恢复。
它从原快照的账户目录、API、scope 和不可变 `simulation_reserved` 事件重建发送身份，
不从提出公式的时间猜发送时间。缺记录就拒绝。保留原快照、原结果和预算，只追加恢复证据；旧评审包不能因此直接提交。

`brain.alpha_list` 默认 `/users/self/alphas`，要求 `count/results` 分页。
当前账户真实 schema 仍待验收；权限由服务端决定。

### 设置协议

`reconciliation.KEY_SETTINGS` 固定 instrumentType、region、universe、delay、decay、neutralization、
truncation、pasteurization、unitHandling、nanHandling、language、visualization、testPeriod，以及显式请求的 startDate/endDate。
逐一比较请求指定的字段，布尔值不能冒充数字；未知请求参数必须更新协议后才支持。
服务端附加字段列于 `server_extra_fields`；附加 startDate/endDate 不引起误拒绝，也不作为 IS 边界证据。
请求主动指定的日期仍需一致；真实参数冲突绝不忽略。

## 2. 已有四 Alpha 的证据审计

在本地建立 `state/existing-alphas.json`，为四个对象填写原始公式和原始关键设置。
条目格式如下；示例不是实际四个 Alpha 的身份或设置，应按真实记录补成四条。

```json
[
  {
    "alpha_id": "REPLACE_WITH_EXISTING_ALPHA_ID",
    "expression": "rank(close)",
    "settings": {
      "instrumentType": "EQUITY", "region": "USA", "universe": "TOP3000",
      "delay": 1, "language": "FASTEXPR", "decay": 4,
      "neutralization": "SUBINDUSTRY", "truncation": 0.08,
      "pasteurization": "ON", "unitHandling": "VERIFY", "nanHandling": "OFF",
      "visualization": false
    }
  }
]
```

```bash
python -m alpharesearch audit-alphas --manifest state/existing-alphas.json --output state/alphas-audit-001.json
```

真实研究/提交开关可保持关闭。凭据只在本机环境变量 `BRAIN_EMAIL/BRAIN_PASSWORD` 或终端输入，密码不回显；
不要写进聊天或项目文件。认证可能使用登录 POST，但命令没有 Simulation/submit POST。
输出已存在时不覆盖；复核使用新输出文件。

逐个读取详情、Check、自相关与 PnL；某项不可用仍保留其他对象的结果。
报告包括原始/观察公式、设置、指标、冲突、GET 来源、响应哈希和缺失证据。
`.shapes.jsonl` 仅留脱敏结构，审计正文是私有操作记录，不反馈给 Agent。

未核实语义时可 GET PnL 调查，但只保留 schema 声明、日期范围、条数、重复/无效日期和哈希，
不保存原始 PnL 数值，不推算日收益或稳定性。无可靠日历时 `missing_dates=null`；不能把工作日当成实际会话。

可靠日频证据必须有：

1. 账户核实的单位、累计/日频语义、会话收盘时间、费用、本金变化和重置依据。
2. 本版仅支持 `cumulative_cash_pnl_constant_capital_session_close`：固定本金、无重置、收盘累计现金 PnL。
   不支持的语义继续未验证，不通过猜列名或重复差分适配。
3. `pnl_unit` 与 `capital_unit` 均明确且一致。例如真实核实两者 USD 后才填 USD；不默认美元/百分比/基点。
   固定本金来自核实的服务端字段路径。
4. 经过审核的 Alpha `is` 精确边界元数据契约，不能用年度列表或 settings 日期替代。
5. 实际市场日历 CSV、完整覆盖、来源、区域与 SHA-256。14 天首尾/内部间隔检查只是异常检测。
6. 全部预期 IS 会话的缺失、重复、非会话日期和跨缺口差分校验。

全部核实才计算既有固定 126 观测窗口、至少 4 窗的诊断。缺单位依据的旧缓存被隔离；
保留历史，补齐真实依据后 GET 重建证据，不手工改 complete 标签。
`real_evidence_acceptance_completed` 是本机操作验收，既不是授权证明，也不表示可提交。

## 3. Check 状态

| 状态 | 解释 | 处理 |
|---|---|---|
| PASS | 对应检查明确通过 | 继续核对其他门槛 |
| FAIL | 明确失败；WARNING 保守归为 FAIL | 拒绝 |
| PENDING | 平台尚未完成 | 缺证据，不可提交 |
| MISSING | 未返回/null/未知状态/无效重复项 | 缺证据，不可提交 |

`SELF_CORRELATION` 无论是否列入自定义 required_checks，都必须明确 PASS。
相关性 max 数字不能代替 Check 完成证据；相关性响应状态 pending/未知时也不用附带数值。
汇总每次从 checks 重算，不信任缓存 PASS 标签。
通过 `audit-alphas` 或 `refresh-evidence RUN_ID TRIAL_ID` 更新；不通过提交触发验证。
平台若只在提交后提供某证据，候选继续等待。
审计缺少扰动、独立验证和多样性全套证明，`ready_to_submit` 始终 false。

## 4. 六公式定向设计

先审核账户、字段并固定配置，再生成计划。改变源码、scope、字段目录、规则或权限配置使计划拒绝执行。

```bash
python -m alpharesearch directed-plan --study-id directed-001 --output state/directed-plan.json --candidates-output state/directed-candidates.json
python -m alpharesearch directed-run --plan state/directed-plan.json --report state/directed-review.json
```

demo 可离线验收。真实运行另需当前账户冒烟记录、已审目录和开启 live_research_enabled；提交开关可保持 false。

| 家族 | 候选 | 相对父项改变 |
|---|---|---|
| 反转 | 原始 5 日价格差 | 基线 |
| 反转 | 5 日价格差 / 5 日前价格 | 收益率归一化 |
| 反转 | 10 日价格差 / 10 日前价格 | lookback 5 → 10，分子分母同步 |
| VWAP | rank(ts_mean((vwap-close)/vwap,1)) | 基线 |
| VWAP | 同结构，平滑 3 会话 | smoothing_sessions 1 → 3 |
| VWAP | 同结构，平滑 5 会话 | smoothing_sessions 3 → 5 |

这些均为未验证假设。平滑是否减少换手、归一化是否改善表现，需要独立结果。
共同 scope 中的 decay 等设置固定；日志保留 parent_key、参数 before/after、公式与协议哈希。
不自动附加邻域实验，新增/失败/未知写均占最多六次预算，也不能超过 program.md 预算。
同一 study_id 绑定同一 run，重启不重置预算。相同公式/设置的已完成结果可复用并保留假设。
每次串行一个任务，创建不确定即停止后续新增。

### 一次性独立比较

使用已授权、未用于发现的独立日频面板，提供 vwap 等字段。
在原有**完整**本地验证计划添加 `"holdout_mode":"directed_fixed_comparisons_v1"`；
仍须 dataset_id、权限、PIT、费用、训练/留出时间、阈值等必填项。
候选文件必须包含完整六公式设计，不能先按 BRAIN 分数过滤。

```bash
python -m alpharesearch validation-freeze --panel licensed-panel.csv --candidates state/directed-candidates.json --plan validation-plan.json --ledger state/directed-validation.sqlite3 --output state/directed-validation.json
python -m alpharesearch final-holdout --manifest state/directed-validation.json --ledger state/directed-validation.sqlite3 --output state/directed-independent-report.json
```

沿用独立登记、稳定 dataset_id 与禁止重叠揭示规则，读留出数值前占用权限。
一次性报告六公式结果及四组父子比较的费用后 Sharpe、换手、rank IC 差值；
不验证后挑赢家，不向 Agent 开放结果，不自动扩大搜索。若根据结果继续修改，下次需未接触的新验证区间。

本地内核未完整复刻 BRAIN 中性化、Decay、Truncation、费用或官方 Sharpe/Fitness。
300 资产/100000 行限制仍在，不能当作 TOP3000 等价验证。
