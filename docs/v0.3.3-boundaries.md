# V0.3.3 — 日历 IS 首尾缺口修复

本补丁针对已复现的反例：声明 IS 为 `2020-07-01..2023-06-30`，日历实际只有 `2021-01-01..2023-01-31`。首尾相差 184 与 150 个自然日；即使审核标志、SHA-256 和中间 PnL 记录格式都正确，也不能把中间片段视为覆盖整个 IS。

## 修复

`pnl_evidence.py` 新增共享的 `validate_session_boundaries()`，使用现有 `MAX_SESSION_CALENDAR_GAP_DAYS = 14` 保守阈值。

- `reviewed_context()` 在按精确 IS 范围筛出会话后，检查 IS 起点到实际首个会话、实际最后会话到 IS 终点的距离。任一超过 14 个自然日时抛出 `ApiError`，不生成可供正常采集流程使用的上下文。
- `daily_evidence_valid()` 对缓存的 `proof.session_dates` 执行同一检查，异常时返回 false。已有 `complete` 标记、格式正确的哈希或足够的中间稳定性窗口都不能覆盖这个拒绝结果。
- 原有内部相邻会话间隔、PnL 覆盖、隔离边界和固定窗口检查继续执行。窗口长度、最少窗数和评价阈值未改变。

历史数据库不重写。旧缓存即使保留 `status=complete`，也必须经过当前校验器复核；不应把单个历史字段当成整个 IS 已验证的证明。该反例的稳定性结果现在为不完整，最差窗口分数为空，不能进入人工提交评审池；核心指标合格时仍可保留研究待验证状态。

## 测试

在修改之前，新增的创建路径和缓存路径回归均失败，分别表现为未抛异常、仍返回 true。修改后 128 项测试全部通过，原有 119 项保留。

新增覆盖：184/150 天完整反例、仅起始缺失、仅末尾缺失、旧缓存复核、稳定性/评价拒绝、0/14/15 天首尾组合、邻近周末边界，以及大日历内合法 IS 子区间。14 天恰好通过、15 天拒绝，只表示此异常检测阈值的边界行为。

## 适用边界

14 天检查不能认证日历权威性，也不能发现所有小于该阈值的漏日。最终仍需经核实、与研究市场一致、完整覆盖所声明范围的交易日历。审核标志和哈希用于防误操作，不能证明缺失日期确为休市，不能防止有文件系统控制权的人伪造输入。

PnL 语义仍需核实固定本金、累计现金单位、无重置及费用/记账方式。真实接口若不同，不能套用合成 fixture。本地组合构建仍不等价于 BRAIN 的 neutralization/Decay/Truncation；本补丁没有声称预测官方 Sharpe/Fitness，也未验证 AI 搜索优于人工或固定规则。

本次没有 BRAIN 凭据，未执行真实 API、真实模拟、真实模型或市场数据实验。真实研究及提交继续默认关闭。离线 Demo 的计数只验证执行链，不证明因子发现能力。

## 升级

保留原研究数据库、共享留出登记和报告。源码变化后，旧 run 的快照保护仍生效，不应强改代码哈希继续运行。新运行对缓存证据使用当前校验器；已暴露留出不会因版本升级重新开放。API 字段契约和固定窗口策略沿用 v0.3.2，详见对应说明。
