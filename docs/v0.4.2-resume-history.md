## 继续研究的统一预览

```bash
python -m alpharesearch resume RUN_ID --continue-research --dry-run
```

此命令只读数据库，不创建 run、不执行迁移、不调用模型或网络，不要求凭据。
预览包括：

- 当前 run 的排队任务、已有结果及待 GET 恢复对象。
- 活跃研究假设需要的固定参数扰动，包含引用其他 run 的已完成候选。
- 去重后的新建需求、本次可能新建上界、已预留次数和原 run 剩余预算。
- 同账户的远程阻塞任务、是否需迁移旧库，以及 `preview_sha256`。

resume 不重新启动 LLM，不生成新研究方向。六公式研究只恢复已登记队列，不扩展冻结设计；
尚未登记的剩余公式仍由 `directed-run` 按原计划处理。
已拒绝的非法公式不参与新建估计，不会阻止其他合法任务的预览。

确认后执行，例如本次最多两次新建：

```bash
python -m alpharesearch resume RUN_ID --continue-research --confirm-preview PREVIEW_SHA256 --max-new-simulations 2
```

使用刚才输出的哈希，不要把示例占位符原样运行。
真实研究可能新建时，CLI 在登录前检查确认；执行器在认证后再次检查。
源码、设置、原预算、队列、假设状态或远程引用变化使旧哈希失效，须重新 dry-run。
执行器只允许本次预览中的新建公式，并在 SQLite 预留事务中执行次数上限。

本次上限按新增次数计算，不把历史支出误当成本次上限。例如已花 5 次、本次允许 2 次，
绝对上限为 7，且仍不能超过 program.md 总预算或六公式协议上限。
原排队任务和新参数扰动共用这两次预算；失败与不确定响应同样计数，不返还预算。
到达上限时剩余任务保持排队，不自动扩大上限。下次继续前重新预览。

`--max-new-simulations 0` 禁止本次新建。已完成缓存和 GET 恢复不占新建预算。
即使目标 run 没有任何可新建任务，执行器也不会使用剩余总预算扩大队列。
普通 `Engine.resume(continue_research=True, ...)` 同样执行确认，不能通过直接调用执行器跳过。

## 普通恢复保持 GET-only

```bash
python -m alpharesearch resume RUN_ID
python -m alpharesearch resume RUN_ID --dry-run
```

普通恢复不接受新建确认参数，不创建 queued，也不扩展扰动。
执行器对普通恢复设置零新增许可；异常 queued/unresolved 标记也不能触发新 POST。
若存在未解决的远程任务，先通过普通恢复或 `recover-trial` 对账，再重新预览继续研究。
串行锁与预算确认互相独立；确认次数不会解开未解决远程任务的锁。

## 损坏的历史指标

`remote_result_complete()` 现在先验证 trial、payload、snapshot 和 metrics 的容器类型，
再读取 Sharpe/Fitness/Turnover。null、数组、字符串、缺失或非有限数值均不构成远程完成证据。
不会猜零值、把 null 当空的合格指标，或单纯吞掉 AttributeError 后标记完成。
正常的有限零值仍可表明计算已结束；是否满足研究门槛由评价器独立判断。

迁移逐条保留原始结果、原 run 快照、预算与审计历史：

- 无法确认完成的损坏记录标记 `remote_state=unresolved`，继续占用其账户串行锁。
- 正常记录照常迁移；一条坏记录不阻止整个数据库升级。
- 重复执行迁移不会重置预算或改写历史。
- 对已有 Alpha 的完成确认也复用类型检查，异常 metrics 不能释放远程容量。

```bash
python -m alpharesearch migrate-state
```

这些防护针对完成判断和状态迁移，不等于自动修复所有历史研究数据。
真实指标须在账户环境中 GET 对账，不能手工补造指标或日频证据。

## 旧版本 run 的限制

继续研究仍要求原快照与当前代码、规则及目录一致；升级不会改写旧 run 的快照哈希。
v0.4.1 等旧 run 可迁移数据库并通过 `recover-trial` 只读追加恢复证据，
不能修改快照哈希后继续消耗预算。新的写研究需按当前规则新建计划/研究。
普通恢复与继续研究使用原有 snapshot 校验，跨版本恢复入口没有新增 POST 权限。

## 实际验收边界

新增回归覆盖：缺少确认、认证期间状态变化、零上限、已有支出后的多次继续、
队列与扰动共享预算、跨 run 缓存、冻结设计、未知写响应和只读恢复。
迁移测试同时包含多条坏记录和一条正常记录，确认正常记录继续迁移，历史与预算保持不变。
