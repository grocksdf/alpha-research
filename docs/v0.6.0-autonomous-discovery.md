# v0.6.0：AI 自主 Alpha 发现 MVP

目标是让负责人设定研究目标、范围与预算后，由一个 Research Agent 产生研究假设和公式，
由确定性组件完成校验、去重、实验安排、模拟、反馈和候选报告。负责人审核候选并决定是否提交。
模型不能修改预算、评价器、字段审核、原始结果或提交权限。

## 本次实际交付

| 能力 | 实现 |
|---|---|
| Alpha Idea Generator | 单模型生成机制、预期符号、预测周期、证伪条件、方向、家族和来源声明；不限于历史四个公式 |
| Alpha Formula Generator | 同一结构化提案带表达式；独立 AST 校验字段、类型、算子、参数、延迟与重复结构 |
| Research Planner | 在候选及其确定性敏感性实验的总成本内，优先新公式、较少探索的结构与方向，兼顾相似度及复杂度 |
| Autonomous Research Loop | 生成 → 规划 → 模拟 → 固定评价 → 反馈 → 生成新假设或父假设修订；总预算及每次调用预算均受约束 |
| Candidate Ranking | 先区分可供人工评审、缺证据和被拒绝；展示指标、相关性、敏感性、风险与原固定评价结果 |
| Checkpoint | 稳定 study_id 绑定一个 run；追加记录想法、决策、谱系、反馈与暂停原因；重启不重置额度 |

`DiscoveryAgent` 与 `ResearchAgent` 共用模型协议、调用计数、token 和费用记录，系统中只有一个研究模型。
新版通过唯一 `research_batch` 工具接收结构化提案；模型没有 Simulation、Submit、文件或终端工具。
当前公式白名单仍是项目已审核的 FASTEXPR 子集，不表示覆盖平台全部算子或 VECTOR 数据。

本次公开仓库基线是 **v0.5.0，commit e316f65**。仓库尚无上一轮交付的 v0.5.1 源码；
本版依据已确认的要求补入收益契约双重门禁，并新增回归，不声称与未取得的 v0.5.1 压缩包逐字一致。

## 先跑离线演示

Python 3.11+，标准库即可。在项目根目录依次执行：

```bash
python -m alpharesearch doctor
python -m unittest discover -s tests -v
python -m alpharesearch autonomy-plan --spec examples/autonomy-demo.json --output state/discovery-plan.json
python -m alpharesearch autonomy-run --plan state/discovery-plan.json --dry-run
python -m alpharesearch autonomy-run --plan state/discovery-plan.json --max-new-simulations 3 --steps 1
python -m alpharesearch autonomy-run --plan state/discovery-plan.json --max-new-simulations 3
```

演示使用**固定假设生成器和合成模拟器**，最多 6 次合成模拟，包含参数扰动；LLM 调用为 0。
这验证流程、预算及恢复，不证明 AI 能发现 Alpha。重复运行同一计划会复用原 run 与剩余额度。
报告默认保存在 `state/autonomy-review.json`，包含研究想法、规划依据、反馈、风险和候选排名。
Demo 永远不能进入正式提交名单；测试中模拟的 live 证据也不是实证结果。

`--steps 1` 表示完成一个候选及其允许的敏感性实验后暂停。Ctrl-C 也会留下暂停记录；
它不能撤销已发送的远程请求。若中断发生在创建或轮询中，先恢复对账，不能再创建一个替代模拟。

## 接入真实模型和已授权数据

1. 在本地 `[llm]` 配置兼容当前 Chat Completions + tools 协议的服务和模型名；
   `LLM_API_KEY` 仅从安全运行环境读取。不要把密码、Cookie 或密钥写入计划、代码或聊天。
2. 使用 `examples/autonomy-llm.json` 创建计划。`generator=llm` 会产生真实模型费用，
   即使 `mode=demo` 也是如此；该组合可先验证真实模型与合成模拟器之间的工程衔接。
3. 真实 BRAIN 研究继续要求：账户允许自动研究、同步并审核字段、单 Alpha 冒烟记录、
   `mode=live` 和 `live_research_enabled=true`。本次没有代为开启这些设置。
4. 在确认预览前固定目标、范围和总预算。后续每次继续执行均重新预览并批准本次新建上限。

```bash
python -m alpharesearch autonomy-plan --spec examples/autonomy-llm.json --output state/live-discovery-plan.json
python -m alpharesearch autonomy-run --plan state/live-discovery-plan.json --dry-run
python -m alpharesearch autonomy-run --plan state/live-discovery-plan.json --confirm-preview PREVIEW_SHA256 --max-new-simulations 3
```

用刚才输出的真实 `preview_sha256` 替换占位符。缺确认会在登录前拒绝；认证后执行器再次核对。
研究状态、计划、预算、字段目录、代码、规则或数据库路径变化，旧计划/预览不能继续使用。
预览里的 Simulation 数量是**预算上界**：模型尚未产生公式，不是已知精确次数。
预算包含所有新建尝试和敏感性实验，不会因为错误、暂停、换进程或重跑同一计划而返还。
规划器目前要求候选及尚未缓存的敏感性实验整体可承担，因此可能剩余额度不足以测试一个完整候选。
这时报告显示 `no_affordable_candidate_bundle`，不会擅自增加额度。

## 基本面、量价、微观结构与情绪

四个方向的标识分别为 `fundamental`、`price_volume`、`microstructure`、`sentiment`。
生成器只会看到当前目录中 `point_in_time=true`、延迟允许、类型支持的字段。
OHLCV 等已知价量字段默认归入 `price_volume`；其他字段须由负责人在已同步目录的元数据中标注方向：

```json
{
  "kind": "MATRIX",
  "point_in_time": true,
  "min_delay": 1,
  "research_domains": ["fundamental"],
  "review_note": "填写该真实账户字段的授权范围、发布时间和修订处理审核依据"
}
```

示例仅说明元数据格式，不提供或虚构一个可用的 BRAIN 字段 ID。
方向标签不授予数据权限，也不替代时点审核。没有授权字段时报告 `needs_authorized_fields`，
模型不得用不存在的字段测试该方向。默认 Demo 目录只提供价量数据，不能声称已经探索其余三类。
更大目录按方向每次轮换最多 40 个字段，附分组字段；这是有界目录切片，不是全目录穷举。
外部 Tick/L2 或情绪数据不能默认用于普通 BRAIN 表达式。

`research_notes` 可提供论文摘要、市场机制、已有因子及已知失败约束；已有 `paper-search` 可单独检索元数据。
本版生成器不自动上网下载论文全文。来源文本是待核实的研究归属，不能当作已验证引文。
当前研究反馈与同范围历史发现记忆会参与下一轮生成；只有固定允许的指标与研究记录能进入模型，
最终留出、前瞻数据、收益文档和 API 原始正文均不通过这些反馈路径暴露。

## 暂停与恢复

```bash
# GET-only：不调用模型、不创建模拟、不增加敏感性实验
python -m alpharesearch autonomy-recover --plan state/live-discovery-plan.json
# 完成恢复后重新预览，再明确批准继续研究
python -m alpharesearch autonomy-run --plan state/live-discovery-plan.json --dry-run
```

普通 `resume RUN_ID` 也维持 GET-only 语义。自主研究不能通过通用
`resume --continue-research` 或旧 Agent 的 `propose_candidate` 扩展，须经过自主计划的规划与确认入口。
同账户/API 跨 run 的未完成模拟继续由原数据库事务锁拦截；创建结果不确定时禁止自动重发 POST。
Location 失效仍走已有 Alpha 列表/详情 GET 恢复；无法唯一核实则保留未解决状态。
恢复后的研究仍是原 run，总预算不重置。计划还绑定数据库路径，避免误换数据库造成额度重置。
本地账本是防误操作机制，不能防止拥有文件系统权限的人删除、重建或篡改整个研究环境。

## 收益契约和人工提交

评价器现在要求 `return_verification.status=verified`，并重新验证完整收益文档。
它还核对当前 Alpha、账户、公式、设置、IS 边界、日历、日收益序列和评审指纹。
最终提交入口再次独立执行相同的文档验证并绑定**当前登录目录账户和精确获批 Alpha ID**。
即使把排名/评价器强制改成通过，缺失或错误的收益契约仍应在预留提交记录前被拒绝。
新增失败回归的 Submit 调用数均为 0；`submission_enabled` 默认保持 false。

自主循环只输出候选。真正提交仍使用现有精确人工审批命令，必须批准评审包中的单个 Alpha；
没有增加批量提交或模型提交能力。缺收益、稳定性、相关性或平台 Check 证据的候选可保留待验证，
不能因此冒充“满足提交条件”。IS 搜索反馈不是独立样本外证据。

## 升级与后续路线

升级前备份数据库、已审核配置、计划和报告。只读 `migrate-state` 会追加新的
`autonomous_studies` 绑定表，原 runs/results/events/预算保持原样。
旧 run 的代码快照不会被升级覆盖；跨版本未完成任务使用原有 `recover-trial` 只读恢复，
不能把旧冻结计划的哈希改成新版本后继续研究。

| 版本 | 开发重点 | 验收方向 |
|---|---|---|
| v0.5.1 基础 | 保留收益契约、证据隔离及人工提交门禁 | 双层失败用例零 Submit |
| v0.6 本版 | 自主发现 MVP 与基本实验闭环 | 不依赖四个历史公式；可记录、规划、暂停及续跑 |
| v0.7 | 真实自动实验闭环产品化 | 在账户核实后，按批准预算完成模拟、补证、分析、改进和故障恢复 |
| v0.8 | 持续学习与因子演化 | 基于可追溯的成功/失败经验减少无效与重复探索 |
| v0.9 | 高质量候选筛选 | 稳健性、低相关、完整证据与条件满足率，同预算对照 |
| v1.0 | AI Alpha Factory | 持续研究、可复现候选报告、人工正式提交 |

PBO、DSR 和成本压力分析继续复用 v0.5.0 的实现，不为增加统计数值而扩大真实模拟数量。
候选的经济有效性、模型相对固定规则的优势、真实接口兼容性仍须分别验收。
本版未执行真实 BRAIN 登录、Simulation、Submit、真实模型推理或真实四 Alpha 的 Phase C 审计。
