# v0.4.1：严格串行、严格解析与实验预览

本版继续修补研究执行正确性，不增加 Agent。真实 API 和 PnL 契约仍未核实。

## 账户级串行互斥

`Memory.claim()` 在 `BEGIN IMMEDIATE` 中检查和预留，另一个连接/进程不能同时取得同一槽位。
锁的身份是同一账户指纹与同一 HTTPS API origin，不再按 run、scope 或公式上下文分开。
省略真实账户身份、换 API 地址与原快照不符时，创建会被拒绝。

| 本地状态/远程状态 | 新任务能否创建 |
|---|---|
| dispatching、uncertain、polling | 否 |
| paused，远程 unresolved | 否 |
| failed/abandoned，远程仍 unresolved | 否 |
| paused，详情已对账确认远程 completed | 可以，仅表示容量释放 |
| failed，服务端明确拒绝创建且 not_created | 可以，已占预算不返还 |
| completed，但核心详情仍不足以确认远程结束 | 否，继续只读恢复 |
| completed 且远程完成 | 可以 |

本地暂停、失败标志以及 Alpha ID 绑定本身都不能证明远程资源已释放。
必须读取已有 Alpha 详情，核对 ID、公式、原始关键设置以及核心指标，才能记录远程完成。
Check 的 PENDING 与远程 Simulation 是否结束是两回事：已确认模拟结束可释放容量，
但 Self Correlation 未 PASS 仍不可提交。

这保证通过**同一 SQLite 研究队列**创建的模拟串行；不能控制账户本人在网页操作、独立冒烟脚本、
外部程序或使用另一份数据库的机器。真实部署须统一使用一个队列，不能用多个独立数据库并发消耗同一账户资源。

## 旧库迁移与恢复

```bash
python -m alpharesearch migrate-state
python -m alpharesearch recover-trial OLD_RUN_ID TRIAL_ID
```

迁移是本地状态升级，不访问网络，不改变原 run 快照、历史结果和预算。
旧 queued 未发送记录标为 not_started；有足够完成证据的结果标为 completed；
旧 paused、失败或证据不足的记录保守标为 unresolved。仅有 Alpha ID 不算完成依据。
迁移可重复执行，不重置任务。保留原数据库及其归档，不能删除锁记录重新获得预算。

dry-run 不执行迁移，旧库会显示 `schema_migration_required=true`。
真实新建前须先迁移，再获得新的预览。被锁住的任务通过 GET 恢复；
找不到唯一 Alpha 时保持未解决，不能为了释放锁重发原 Simulation POST。
旧版本快照依旧不能执行新研究；跨版本只读恢复仍可追加证据。

## Recordset 严格解析

数组记录必须提供明确 schema。字段名称是非空、无首尾空白且唯一的字符串；
重复 pnl 列直接报错，不能通过 zip/dict 静默覆盖。带 schema 的对象记录必须与声明字段完全一致。
即使 records 为空，也检查已提供的 schema。无 schema 的普通对象记录仍兼容，但字段名同样必须有效。
本修复不表示真实 BRAIN 曾返回重复列名，也不证明 PnL 单位或累计语义。

## 不联网的 dry-run

```bash
python -m alpharesearch run --agent baseline --dry-run
python -m alpharesearch run --agent file --candidates candidates.json --dry-run
python -m alpharesearch run --agent llm --dry-run
python -m alpharesearch directed-run --plan state/directed-plan.json --dry-run
```

预览只读取配置、冻结设计和已有数据库；不会创建数据库、run、实验、报告或授权请求，
也不调用真实模型。已有 SQLite 使用只读连接，不运行 Memory 的迁移。

主要字段：

| 字段 | 含义 |
|---|---|
| items.action | create / reuse / get_recovery_only / wait_for_original_run |
| new_simulations_needed | 固定公式去重后的预计新建需求，含确定性扰动；LLM 未知时为 null |
| new_simulations_upper_bound | 在剩余协议预算内，本次可能新建的上界 |
| simulations_already_reserved | 固定研究已预留次数，含失败和不确定写 |
| remaining_budget | 协议预算减去已预留次数 |
| remote_blockers | 同账户尚未解决的远程任务 |
| schema_migration_required | 是否需先离线迁移旧库 |
| preview_sha256 | 代码/规则/设置/输入/候选状态/预算与阻塞记录的确认哈希 |

固定候选是估计而非承诺，实际 API 可能失败；LLM 未生成公式前不能精确估计新建数。
预览报告不表示 BRAIN 配额或权限已确认。服务端仍独立决定限流和访问权限。

## 显式确认本次新建上限

真实 `run` 和 `directed-run` 如可能新建模拟，必须提供当前预览哈希及次数上限：

```bash
python -m alpharesearch directed-run --plan state/directed-plan.json --confirm-preview PREVIEW_SHA256 --max-new-simulations 2
python -m alpharesearch run --agent baseline --confirm-preview PREVIEW_SHA256 --max-new-simulations 3
```

这两条是格式示例，要使用各自命令刚输出的哈希。两次预览不能交叉确认。
参数、源码、字段目录、预算或任务状态变化时哈希失效；校验失败不会登录后强行创建。
实际执行在认证后也会复核，创建事务仍受串行锁和次数上限保护。
上限包含失败和不确定写，不因重启退回预算。已完成缓存和 GET 恢复不消耗新建次数。
0 表示本次不允许新建；协议总预算也不能被本次上限扩大。

定向流程可用较小上限分批执行，达到本次上限保存报告并停止。
下次先重新 dry-run，再确认剩余次数；同一 study_id 仍复用同一 run，总计最多六次。
普通研究 `resume` 默认仍仅 GET。自 v0.4.2 起，`--continue-research` 同样需要预览确认与本次新建上限；
v0.4.1 曾保留的原预算继续入口已被替换，详见 [v0.4.2 说明](v0.4.2-resume-history.md)。

v0.4.0 冻结计划因源码哈希变化不能直接用于新研究；不要编辑计划哈希解除保护。
先用原数据库恢复远程任务，保存旧结果，再按当前源码与固定规则创建新的研究计划。

## CI 与发布校验

CI 配置为 push/pull_request 触发，覆盖 Ubuntu/Windows 和 Python 3.11/3.12/3.13。
官方 checkout/setup-python action 固定到从各自官方仓库核对过的提交。
工作流只读仓库权限，测试不使用 BRAIN 或模型凭据，未配置提交、部署或真实模拟步骤。
本次只创建和本地检查了配置，没有推送仓库，没有实际运行远程 CI。

```bash
python scripts/release.py --check
python -m unittest discover -s tests -v
python scripts/release.py --output dist/AlphaResearch-v0.4.1.zip --verify-archive dist/AlphaResearch-v0.4.1.zip
```

维护源码后主动更新清单：`python scripts/release.py --refresh-manifest --check`。
CI 不会自动更新清单掩盖未登记变更。
打包仅允许源码、演示配置、文档、示例、测试、脚本和 CI 配置；数据库、真实账户配置、环境文件和缓存不进入发布包。
ZIP 成员必须与清单完全相符，拒绝额外成员、重复成员和哈希变化；同样源码生成同样的 ZIP。
凭据扫描检查常见服务密钥、私钥头和字面量凭据赋值，只报告路径/行号/规则，不回显匹配值。
这是有限模式检查，不能替代凭据管理或完整安全审计。跨平台检出使用 LF，以保持清单哈希一致。

本次所有 API 响应、价格和比较结果均为合成数据。
账户列表分页、详情、Check、PnL 的真实结构及单位、累计/日频语义、IS 边界、日历仍待账户只读验收。
