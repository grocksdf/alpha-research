# v0.6.1：修复完整收益契约门禁回归

本版直接在已交付的 **v0.6.0** 上修复。`autonomy.py`、`discovery.py` 和原有
29 项自主研究测试保持逐字一致，没有退回 v0.5.0，也没有改变研究预算、父子谱系或断点机制。
真实研究和提交开关默认仍关闭；本轮没有真实 BRAIN、模型、Simulation 或 Submit 调用。

## 已复现并修复

| 离线构造场景 | v0.6.0 复现 | v0.6.1 要求 |
|---|---|---|
| PnL 或详情来源标为 POST | 未拒绝 | 必须显式 GET |
| API 来源与文档、响应路径或当前配置不一致 | 未完整核对 | 拒绝来源冲突 |
| evidence_source 的 Alpha ID 不一致 | 未拒绝 | 逐处绑定获批 Alpha |
| 文档改为 EUR、原始 PnL 仍为 USD，并重算摘要 | 未拒绝 | 文档、PnL、本金和当前审核币种一致 |
| verified 同时附未解决 reasons | 未拒绝 | reasons 只能缺省或为空列表 |
| 契约明确 insufficient_evidence | ready=false 但仍有窗口分数 | 不计算可信稳定性分数 |

上述复现全部使用合成数据。旧版约 4.1 的窗口 Sharpe 只是复现用数值，不是金融业绩。
没有证据表明旧版已向平台发送真实错误提交。

## 一个统一验证器，三处直接使用

`require_result_return_contract()` 是完整验证逻辑的唯一实现，成功返回不可变的
`VerifiedReturnSeries`，失败抛出 `EvidenceError`。以下路径分别直接调用：

- 评价器：决定候选证据是否足以进入人工评审。
- 固定窗口统计：决定是否允许计算稳定性分数。
- `Engine.submit()`：重新获取当前证据后独立验证，成功后才能预留提交记录或调用 `submit_once()`。

`submission_return_errors()` 只保留为兼容视图，内部委托统一验证器，不再另写一套较弱规则。
即使把候选排名强制改为 ready、伪造报告通过，或令兼容视图返回空错误列表，最终提交仍独立执行完整验证。
这不是防止拥有代码/文件系统权限的人任意重写程序的安全边界。

校验覆盖：

- 实时账户模式、非合成来源、当前账户和明确获批的 Alpha ID。
- 文档 API、结果 API、当前 API、详情/PnL 端点、GET 方法、响应身份和有效摘要。
- 公式与设置指纹、当前研究设置及原详情对账摘要。
- 原始 PnL 与文档币种、本金币种、固定本金数值、来源字段路径和详情响应摘要。
- 累计现金 PnL、固定本金、无重置、成本审核、净/毛收益及成本模型与备注。
- 精确 IS 边界、研究样本、日历身份/区域/来源/覆盖/指纹、完整交易会话。
- 原始 PnL 差分、归一日收益、文档重算收益、观测日期和归一结果摘要。
- 全部审核摘要字段、未解决原因、未解决收益证据错误，以及当前审核配置。

允许同一 HTTPS 地址的默认 443 端口和等价绝对 GET 路径；不会因为这种等价表示误拒绝。
API 跨主机、降级、含凭据、查询/fragment 或路径冲突均不能通过。

## 缺证据时只保留覆盖诊断

契约未通过时，`worst_window_sharpe`、`positive_window_fraction` 及每窗 `sharpe` 均为 `None`，
`stability.complete=false`。代码不调用数值窗口计算函数，只保留固定锚点的日期、观测数和覆盖率。
这也适用于证据探测和已有 Alpha 审计；“日频观测完整”不等于“完整收益契约已验证”。
若核心平台指标可读且未触发硬拒绝，候选仍可保留待验证，不能进入人工提交名单。

随后恢复正确证据的正例可以通过一次，避免把“所有提交一律关闭”误当作门禁正确。
这些调用全是本地测试替身；没有实际网络请求。

## 升级和已有证据

1. 先备份数据库、已审核配置、研究计划和报告。安装完整包，或将增量补丁应用到未修改的 v0.6.0 源码。
2. 运行 `python -m unittest discover -s tests -v` 和 `python -m alpharesearch doctor`。
3. 不要给旧证据直接补 `verified` 标签、改币种或改摘要。v0.6.0 缓存缺少新增来源与成本绑定时，按证据不足处理。
4. 已完成 Alpha 可通过现有 `audit-alphas` 入口重新 GET 取证；同版本运行中的已有候选可通过 `refresh-evidence` 刷新。
   跨版本未完成任务使用 `recover-trial` 只读恢复；不新增模拟、不自动重发未知 POST。
5. 原实验代码快照保持冻结，旧计划/旧评审包不会被自动升级成可提交。不能改旧计划哈希绕过快照校验。

本版不增加数据库迁移或自动批量执行入口。自主研究的同计划续跑、预算和谱系逻辑保持 v0.6.0 行为；
源码版本变化依然触发原有快照保护。真实 API、收益口径、账户完整历史和独立市场有效性仍须单独验收。
