# v0.5.1：收益契约双层提交门禁

修复 v0.5.0 的一致性缺口：旧 PnL、稳定性、相关性和平台指标通过时，`evaluate()` 没有读取新增 `return_verification`。因此成本口径未验证也可能被标为 ready；`Engine.submit()` 当时仍只依赖同一评价器重新计算的 shortlist。

默认提交开关始终关闭，本次未发现或执行真实误提交。本补丁没有开启开关、增加模拟、扩大 PBO 候选数或实现演化执行器。

## 评价器门禁

- 新收益契约是候选证据的必需项，适用于新结果和历史缓存；不存在、null、错误类型、非 `verified`、旧摘要不匹配都进入 `missing: unverified_return_contract`。
- 重新运行收益文档校验，不单凭状态字符串。成本、本金、单位、IS 和日历仍须通过原有契约。
- 核对文档与当前结果的 Alpha ID、账户引用、公式、完整观测设置、GET 响应哈希、累计现金 PnL 语义、资本基数、交易会话及每日收益值。
- 合成文档或其他来源的独立面板不能充当真实 BRAIN 提交证据；真实设置比较仍沿用关键字段协议，服务端附加日期不被当成 IS 证明。
- 契约不完整时不生成候选稳定性分数；原始平台 Sharpe/Fitness/Turnover 保留。无其他硬拒绝的公式仍可进入 research_queue 补证，不会伪造缺失值。

评价输出含嵌套的 `return_verification` 复核结果及阻断原因。高 Sharpe、PBO、DSR 或 Check PASS 均不能覆盖这一缺口；有效契约也不能覆盖 Self Correlation PENDING。

## 独立最终门禁

`Engine.submit()` 保留原有开关、精确 Alpha ID 人工批准、已归档评审包哈希、版本快照和最新 shortlist 检查。重新 GET 取证并保存后，提交函数自身还会再次调用纯校验器：

1. 复核原始契约和全部数据绑定；
2. 要求最新结果的 ID 等于获批 ID；
3. 要求证据属于当前配置账户与 API；
4. 通过后才允许创建 `submissions` 意图记录和调用 `submit_once()`。

这次调用独立于 `evaluate()` 的返回值。回归测试强制评价器 ready，或强制使用过期 shortlist，再提供未验证/缺文档/成本未知/换账户或 Alpha 的新证据，仍然阻断；HTTP stub 的请求数和 `submissions` 记录数均为 0。

两层复用同一契约校验函数，减少规则漂移；调用点独立，不是要求第二个人审核，也不是远程平台签名认证。文件审核记录仍是防误操作机制。

## 历史与升级

没有新增数据库迁移。原始结果、预算和快照不重写；新一轮 GET 证据以已有追加结果机制保存。旧缓存缺新契约会在重新评估时成为缺证据，不能沿用旧 ready 标签提交。

补丁相对交付的 v0.5.0 ZIP。先备份 SQLite（包含 WAL 状态，宜用 backup API）和旧源码，再检查并应用：

```bash
git apply --check AlphaResearch-v0.5.0-to-v0.5.1.patch
git apply AlphaResearch-v0.5.0-to-v0.5.1.patch
python -m alpharesearch doctor
python -m unittest discover -s tests -q
```

代码哈希改变后，旧 run 的继续研究/提交评审包按原规则失效。使用 `recover-trial` 对旧任务只读对账，不改快照、预算或手工涂改摘要。回滚源码可以反向应用补丁，但旧版本仍有本次门禁缺口；旧版不得开放正式提交。

## 真实验收状态

本次无账户凭据和 Phase C 四个 Alpha 清单，真实 GET 审计仍未执行。真实市场日历、本金、成本语义和完整账户试验史仍待验收；没有模型调用、真实 Simulation、真实 Submit、GitHub 推送或远程 CI。

PBO 至少八候选的规则不变，它是本项目的保守研究门槛，不是 BRAIN 要求，也不能保证统计可靠性。不要为了得到 PBO 数值增加真实实验。
