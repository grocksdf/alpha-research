# V0.3.1 修复与升级说明

本版本修复 V0.3.0 两个研究证据隔离问题。测试使用合成数据和脚本化 API 响应；真实 BRAIN 账户、真实市场数据及 AI 发现有效 Alpha 的能力仍未验收。

## 1. 最终留出重复揭示

旧锁依赖文件字节哈希。新增回归在旧版上确认：重排相同 CSV 的数据行、换 study_id 和实验账本后，留出再次执行成功。

现在文件 SHA-256 只负责冻结后的完整性检查。权限身份为 `dataset_id + [holdout_start, holdout_end] + local-daily-final-v1`，所有研究共享 `[validation] holdout_registry`。协议由代码固定，计划不能自行发明新协议获得额度。同一数据身份下，已经预留、执行失败、已完成或历史导入的区间及其重叠区间全部拒绝。

登记与研究数据库、每个实验 `--ledger` 分离。新 study_id、新实验账本、不同发现期内容均不能重置同一数据身份的权限。冻结 manifest 保存登记路径及登记 UUID；执行时缺失文件或登记身份变更会停止，不自动创建空登记。

在解析留出观察值之前，SQLite `BEGIN IMMEDIATE` 原子消费权限。随后把留出区间中的观察行按字段名和数值语义规范化，再排序哈希；行顺序、列顺序、CSV 引号/换行及等值数值格式不改变该辅助指纹。指纹重复会拦截误改 dataset_id 的相同数据。登记成功后崩溃或评价失败都不自动释放权限；只能读取已归档报告，无报告时不得通过重试重新使用同一区间。

这不是对操作者的安全隔离。持有文件系统控制权的人能删除所有登记、伪造身份或更改代码。规范化指纹也不能识别所有经过增删列、增删记录或更改区间的数据别名。数据负责人必须维护稳定身份，保留登记备份，并统一协调多机器。若需要防恶意重置，应部署独立权限和备份的登记服务；本版本没有声称具备这种隔离。

### 升级已有实验

先备份源码、所有实验账本、最终报告及原始数据。已揭示的数据不会因升级重新成为样本外。

为每个逻辑数据集指定永久 `dataset_id`，加入新研究计划 JSON。确认 `[validation] holdout_registry` 是固定共享路径，不随研究新建。对该数据集所有包含旧版揭示记录的账本执行：

```bash
python -m alpharesearch validation-import-legacy --ledger path/to/old-validation.sqlite3 --dataset-id YOUR_STABLE_DATASET_ID
```

命令仅读取旧 manifest 的时间范围，把全部已占用区间保守登记；不读取面板、不重新计算历史表现。重复导入幂等，重叠区间各自完整保留。命令按提供的身份导入账本中全部暴露区间；若一个旧账本包含不同数据集，应先由负责人核对身份并按数据集整理可信的迁移记录，不能猜测。未提供的旧账本无法被自动发现。

发现旧账本含未导入的暴露记录时，新冻结拒绝继续。旧版 manifest 不继续执行最终揭示。`validation-result` 仍能读取原来保存的最终报告。新预注册仅应用于尚未使用的数据区间；研究账本可以更新，共享揭示登记须保留。

## 2. BRAIN 精确 IS/OS 隔离

旧代码用年度统计返回的年份过滤累计 PnL 差分，无法排除同一年中分割日期之后的 OS 值。现在完全取消该推断。

`[brain.discovery_evidence]` 默认为未核实：

```toml
schema_reviewed = false
review_note = ""
date_semantics = "unverified"
is_start_path = []
is_end_path = []
```

适配器只有在负责人根据当前账户真实响应核实了详情 `is` 内的精确日期字段、包含端点语义和记录集语义后才接受契约。路径为服务器响应字段路径数组；本版本未提供可冒充真实账户契约的默认字段名。测试中的 `is.startDate/endDate` 仅是 fixture，不能作为真实接口文档。当前实现仅支持明确的 `YYYY-MM-DD` 包含区间；时间戳、时区或其他样本区域语义不明时保守拒绝，须另写经核实的适配器。

无可靠边界时，不请求年度统计/PnL 记录集，不生成年份白名单，报告明确缺失原因。有可靠边界时，先按记录日期计算累计 PnL 差分，再要求其两个端点都在精确 IS 区间内；不能只检查右端点或先删 OS 点再连接两侧数据。按年汇总仅保留全年完全位于 IS 的年份；分割所在的部分年份不用于年度稳定性评价。它的合规 IS 日频差分仍可保留，不依赖年度汇总是否存在。

序列附带隔离协议、精确边界、服务器元数据路径和契约哈希。旧缓存没有这些信息，或区间越界时，不可用于提交评审/多样性筛选；报告隔离其年度和 PnL 字段，原数据库历史记录不修改。来源记录是本地可审查的操作证据，不是平台签名或不可伪造的授权凭证。

## 3. 研究队列与评审候选

`research_queue` 保存核心 Sharpe、Fitness、Turnover 门槛通过且无已知拒绝项、但年度/相关性/PnL/扰动等证据不完整的公式，标记 `research_status=continue_research`。不对缺失指标补零，也不把这些公式列为可提交。

`shortlist` 仍要求全部固定门槛、可审查的精确序列隔离及多样性条件，通过后才可人工评审。它不代表平台最终会接收。缺少一个核心指标也不会掩盖另一个已知失败项。

可对当前研究引用且已拥有 Alpha ID 的候选只读刷新证据：

```bash
python -m alpharesearch refresh-evidence RUN_ID TRIAL_ID --report state/refreshed-review.json
```

该命令仅 GET，同一 Alpha 不创建新模拟，证据追加保存，模拟预算不增加。配置/源码需匹配该 run 的冻结快照；更改契约或评价规则后不能悄悄恢复旧 run。新研究应明确记录新协议及缓存来源。

## 4. 真实普通账户验收仍待执行

本次环境没有 BRAIN 凭据或 LLM 密钥，未执行真实登录、目录探测、模拟、提交或外部模型调用。默认真实研究和提交继续关闭。

在本人本机依次执行：

```bash
python -m alpharesearch doctor
python -m alpharesearch probe-api --output state/catalog-probe.json
python -m alpharesearch probe-api --one-simulation --expression "rank(close)" --output state/smoke-001.json
python -m alpharesearch resume-probe state/smoke-001.json
```

最后一条只在探测处于轮询/指标读取未完成状态时运行，用于确认 GET 恢复，不再 POST。完整后再次恢复会拒绝。账户密码只在本机隐藏输入或安全环境变量中提供；验证码等额外验证交回官方流程。结构文件用于审查 shape，私有运行记录保留恢复必要信息，不作为公开样例发出。

单模拟验收证明的范围是账号该次模拟、指标解析与恢复路径。`account_http` 等本地 JSON 标记能被拥有文件权限的人伪造，是防误操作检查；所有权限以服务端判断为准。单模拟完成也不证明 PnL 分割契约正确，后者须单独核实。缺少分割元数据的账户仍能保留研究候选，但不能被标记为证据完整。
