## 1. 统一收益契约

`return_contract.py` 仅从审核完整的文档构造不可变 `VerifiedReturnSeries`。分析器拒绝原始数组或仅标记 `complete` 的缓存。

输入文档包含：

- `candidate_id`、明确布尔 `synthetic`；
- `contract.protocol=verified-return-contract-v1`、`source_type=brain_pnl/independent_pit_panel`、来源 ID、稳定 population ID、区域/Universe/delay；
- BRAIN 的账户引用、公式/设置哈希；独立面板的 dataset ID 与 PIT 审核；
- `reviewed/review_note/review_source_sha256`，已核实 IS 精确日期，`sample_role=research_is`；OS 等排除区间不得与 IS 重叠；
- 已审核成本口径：布尔 `net_of_costs`、`costs_reviewed`、`cost_model_id` 和说明；
- `calendar` 的审核来源、区域、覆盖边界、完整 sessions 和规范化 SHA-256；
- 有序唯一的 `{date,value}` 观测，以及 `data_sha256=digest(observations)`。

| value_semantics | 单位与本金约束 | 转换 |
|---|---|---|
| daily_cash_pnl | 明确货币单位、同单位正固定本金、无重置/现金流已核实 | 当日金额 / 固定本金 |
| cumulative_cash_pnl | 同上；必须完整覆盖每个已审核交易会话 | 相邻会话累计差 / 固定本金；首条仅作锚点 |
| nav | 已核实总回报 NAV，正数，无外部现金流/重置，分红语义已审核 | NAV 比率 - 1；首条仅作锚点 |
| daily_return | 明确 `fraction`，已审核为 simple_return，不接受百分数或基点猜测 | 原值 |

现金 PnL 固定本金归一与复利 NAV 的分母不同，`return_basis` 不同的序列禁止混合比较。不同账户/数据集、Universe、成本模型、合成/真实来源、日历或日期不对齐时，也不做日期交集来绕过问题。

任何缺失日期、重复日期、非有限值、OS 混入、无效净值、未知成本/本金都会阻断新增统计。边界与相邻会话仍使用原有 14 自然日异常检测；**它不能发现 14 天内所有缺会话，更不能认证权威交易日历**。完整性最终依赖针对该市场核实的日历来源。审核标志、哈希和注册时间都是防误操作记录，不是防恶意修改的安全边界。

### 已有 Alpha 的只读证据

原来的清单仍为 `[{"alpha_id":...,"expression":...,"settings":...}]`：

```bash
python -m alpharesearch audit-alphas --manifest state/existing-alphas.json --output state/audit-050-001.json --returns-output state/returns-050-001.json
python -m alpharesearch verify-returns --manifest state/returns-050-001.json --output state/return-review-001.json
```

审计登录后仅 GET 详情、Check、相关性和 PnL，不新建 run/Simulation/Submit。保持公式、关键设置及账户对账。`--returns-output` 为可选私有文件：只有契约完整的 IS 原始观测可导出；缺证据项只包含 ID 与阻断原因。OS 值不导出。不要公开真实收益清单。

`config/settings.toml` 新增成本审核字段，默认全部未验证。必须核实后再填写；不要复制合成示例的成本口径。

```toml
[brain.pnl_evidence]
# 其余单位、本金、日历与 IS 审核字段继续必填。
costs_reviewed = false
net_of_costs = "unverified"  # 核实后才改为真正的 true/false

```

新增审计报告的 `real_evidence_acceptance_completed` 也要求收益契约通过。新统计层不把旧缓存的日频 `complete` 标记直接当作收益认证；旧固定评价器和其历史结果保持原有语义。提交入口仍有独立重新取证和硬门槛。

## 2. 冻结分析协议与 Bootstrap

冻结候选全集、IS 区间、区块长度、seed、次数、置信度、年化频率、固定窗口、参数邻域和成本情景：

```bash
python -m alpharesearch analysis-freeze --spec examples/analysis-spec.json --output state/frozen-analysis.json
python -m alpharesearch robustness-audit --manifest examples/synthetic-returns-manifest.json --protocol state/frozen-analysis.json --output state/robustness-001.json
```

`examples/analysis-spec.json` **仅适配合成示例**。真实研究应在看待评价数据之前另行制定协议，不能照抄候选 ID、日期与合成日历。`frozen_before_observation=true` 是负责人承诺；软件无法从本地文件证明其时间真实性。

Moving Block Bootstrap 从原序列抽取有重叠的连续区块，区块内部保持顺序，拼接后截断为原样本长度；不使用 IID 乱洗。默认示例预先固定 5/10/20 个交易日，全部报告，不选最好区块长度。输出零日无风险基准、样本标准差 Sharpe、percentile CI、seed、实际观测数与抽样结果哈希；观测数不是独立样本数估计。常量序列、历史长度不足、任一 bootstrap 轮无定义或超过明确工作量上限时拒算，不丢弃坏轮次再计算好看的区间。

固定窗口计算与 `pnl_evidence.py` 共用纯函数；示例 126 个日观测一窗、至少 4 窗、从首个观测固定切分。末尾不足一窗的观测会单列，不能解释为全部日期均进入窗口分数。这些协议值是研究选择，不是 BRAIN 官方门槛。Bootstrap 假设仍可能受到结构变化影响，CI 不保证未来收益。

参数邻域必须全部预注册。报告全部邻居的 Sharpe、中位数、最差值、按冻结阈值计算的稳定比例；少邻居则拒算。已核实换手口径时，附每个成本情景下相对基准的日均收益差；否则成本权衡为 null + reason。不改原 evaluator 的阈值，不把邻域胜者自动提交。

## 3. PBO、DSR 与完整尝试历史

```bash
python -m alpharesearch attempt-history --output state/local-attempts-001.json
python -m alpharesearch selection-bias-audit --manifest state/verified-returns.json --protocol state/frozen-analysis.json --output state/selection-bias-001.json
```

`attempt-history` 以 SQLite 只读事务导出全部本地 trials 以及重复提案事件，包含失败、无效、未完成和缓存复用。损坏结果仍保留来源哈希，不被删除。输出 `complete=false`、`reviewed=false`、`dsr_calibration=null`：一个本地库不能证明账户其他实验没有遗漏。重复提案计入尝试清单，不自动视为独立检验。不要把 `total_attempts` 直接填成 `effective_independent_trials`。

收益 manifest 可携带审核后的 `history`。必须有完整 attempts、计数与哈希、外部来源哈希及包括失败/无效/未完成尝试的声明。候选 ID 全集须与冻结协议一致。全部账户历史和相关家族的范围需负责人核实；本地代码不能证明这项声明的真实性。

**PBO：** 本协议保守要求至少 8 候选、252 个完全对齐日观测、8/10/12 个连续时间块，每块至少 21 观测。枚举所有半数训练块，其余作测试；以训练 Sharpe 唯一胜者在测试中的升序 rank 计算 `omega=rank/(N+1)` 和 logit，PBO 为 logit<0 的比例。保存每折胜者、训练/测试块、排名和日期覆盖。并列、少候选、历史缺失、未完成/失败候选无可比收益、坏折或计算上限都会返回 unavailable。四个 Phase C Alpha 不足以通过本协议；八候选只是最低运行门槛，也不保证估计可信。

**DSR：** 使用非年化日 Sharpe、Pearson 峰度和总体中心矩偏度。要求审核过的完整试验 Sharpe 方差（日频）、有效独立试验数（至少 8，不能超过总尝试数）、每条收益的有效观测数与方法。校准必须绑定历史哈希、同口径 population 哈希和收益输入哈希。只提供当前幸存者、独立性未知或样本数未知时不可算。失败的历史不会从计数中删除；未结束尝试阻断 DSR。

实现采用论文中的极值近似阈值与 PSR 正态 CDF，不自动估计独立检验数或序列相关修正，也不拿当前胜者方差冒充全部试验方差。DSR 是有条件的显著性诊断，不是 Alpha 有效的后验概率。PBO/DSR 都不参与覆盖平台硬门槛的加权评分。

## 4. 成本压力与单维计划

成本情景只允许明确的 `incremental_cost`，bps 完全由预注册协议提供，没有复制第三方的固定费用/滑点常数。必须有按日期对齐、同一资本基数的单边交易名义额换手契约，绑定收益输入哈希。已扣成本的收益仅额外扣情景增量，不重复扣原费用。未知换手契约只展示 `assumption_only` 与 null 指标。计算结果始终标记 hypothetical，不冒称 BRAIN Sharpe。

```bash
python -m alpharesearch evolution-plan --spec examples/evolution-study.json --output state/evolution-plan.json
python -m alpharesearch evolution-preview --plan state/evolution-plan.json
```

每个家族只允许一个整数窗口占位符，冻结基准、范围、预期方向与反例。每个变体记录相对基准的唯一参数变化；不增加自动邻居。示例为收益率归一反转和 VWAP 归一偏离平滑。

计划预算默认 0，规划上限不能超过 4 或 program.md。即使写入规划值 4，预览仍明确 `new_simulations_authorized=0`、`new_simulations_upper_bound=0`，另列未来需多少新建。复用现有 preview 的 AST 去重、历史结果与跨 run 远程阻断检查，不创建研究 run、不迁移状态、不登录。源码/目录/规则变化使冻结计划失效。独立验证 manifest 为空时明确显示未绑定。

**没有 `evolution-run` 命令。** 现有六公式协议的 6 次设计上限不是本方案的自动批准。后续开发新执行入口仍须先真实审核、独立验证绑定及原有哈希确认/预算/不确定 POST/串行保护；本版没有替用户批准任何次数。

## 5. 可复现报告与盲测隔离

```bash
python -m alpharesearch research-report --manifest state/verified-returns.json --protocol state/frozen-analysis.json --review state/engine-review.json --output state/research-report-001.json
python -m scripts.demo_robustness --output-dir state/synthetic-report-demo
```

报告把输入/协议哈希作为 analysis_id；同输入重复分析不是新独立证据。可选原 Engine 评审包须通过内容与快照哈希核验，保存 run/trial/Alpha 引用、公式、家族、关键设置、原始平台指标/Check、预算、费用、失败/未完成记录、缺证据原因和统计诊断。

只有原 evaluator 已 ready、Check 完整 PASS、真实收益契约且公式/设置/账户/范围一致时，才沿用 `ready_for_human_review` 标签；新统计高分不能升级原不合格结论。报告里的 `ready_to_submit` 永远 false；本次 `submit_posts=0`、`submission_enabled=false`。历史 POST 次数未核实时保持 null，不能拿本次零请求冒充整个账户历史零提交。

所有新分析命令只写指定的新 JSON，拒绝覆盖，不初始化 Memory/Engine、不登录、不调用模型、不接触最终留出账本或重算盲测。显式 `final_holdout/os/forward` 输入会被拒绝。研究软件无法识别被人恶意重新标注为 IS 的数据；原独立留出登记账本仍须保持完整并限制访问。报告不进入 Agent 的 allowlist 研究反馈。

## 6. 升级、备份和回滚

- 先停止本地 worker，用 SQLite backup API 备份正在使用的数据库；不要只复制仍有 WAL 的主文件。保留原源码、配置、独立留出登记和历史报告。
- 本版**没有新增 SQLite 表或迁移**，分析档案为独立 JSON。原 v0.4.2 数据库、快照、结果、预算和审计记录不被重写，重复打开仍使用已有容错迁移。
- 升级补丁基于交付 v0.4.2 ZIP，不能直接当作原 GitHub v0.3.5 的增量。对干净源码先 `git apply --check PATCH`，再 `git apply PATCH`。
- 回滚为原 v0.4.2 源码或 `git apply -R PATCH`；新增分析 JSON 可留存，但旧程序不读取它们。不要用回滚/改哈希继续跨版本旧 run 的新研究；先 `recover-trial` 只读对账，保留 spent budget。
- 新代码/配置改变快照，旧 `resume --continue-research` 和冻结计划不会自动兼容；不篡改旧快照。现有 GET 恢复接口继续可用。
